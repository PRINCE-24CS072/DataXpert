Last updated March 4, 2026

Overview

What is DataXpert and what makes it special

DataXpert is a modern business analytics platform that leverages AI to provide actionable insights from your business data. Built with a Python Flask backend and vanilla JavaScript frontend, it offers real-time analytics, an AI-powered chat interface, and comprehensive data visualization.

💡 DataXpert follows a clean three-tier architecture: Frontend (HTML/CSS/JS) → REST API (Flask) → Supabase (PostgreSQL). All API calls go through /api/* endpoints.
Key Features
🔐
Dual Authentication

Email/password OR Google OAuth for seamless access. JWT tokens for session management.

📊
Live Dashboard

Real-time business metrics with interactive Chart.js visualizations and time-range filters.

🤖
AI Chat Analysis

Natural language queries for instant insights — ask questions about your sales, profits, and trends.

📈
Anomaly Detection

Automated Z-score based outlier identification across your business data records.

📁
Smart CSV Import

Bulk upload and process business data from CSV/Excel files with auto column mapping.

⚡
DataCache

Client-side sessionStorage cache with 5-minute TTL avoids redundant API calls.

Quick Start

Get DataXpert running locally in minutes

✅ Prerequisites: Python 3.8+, pip, a Supabase account, and optionally a Google Cloud project for OAuth.
  1. 1
    Clone the repository
    Download the project to your local machine.
    bash 
    git clone https://github.com/PRINCE-24CS072/DataXpert.git
cd DataXpert
  2. 2
    Install backend dependencies
    Install all required Python packages.
    bash 
    cd backend
pip install -r requirements.txt
  3. 3
    Configure environment variables
    Create your .env file from the template, then fill in your credentials. See the Configuration section for all required variables.
    bash 
    cp .env.example .env
# Then edit .env with your values
  4. 4
    Set up the database
    Run database.sql in your Supabase SQL Editor to create all tables. See Database Setup for details. Tables created: users, business_data, chats, analysis_results, teams, team_members.
  5. 5
    Start the backend
    The Flask server starts on port 5000.
    bash 
    python app.py
# Server running at http://localhost:5000
  6. 6
    Serve the frontend
    Open a second terminal, navigate to the frontend directory and start the local server.
    bash 
    cd frontend
python -m http.server 5500
# App running at http://localhost:5500
    Alternatively: use the VS Code Live Server extension and click "Go Live".
  7. 7
    Open the app
    Navigate to http://localhost:5500 in your browser. Register a new account and start adding business data from the Dashboard.
Using the App
Adding business data
  • Log in and navigate to the Dashboard.
  • Click Add Data and enter the date, category, sales, expenses (profit is auto-calculated).
  • Or click Upload to import a CSV file. Download the template first via the Upload modal.
AI Analysis
  • Navigate to AI Analysis.
  • Type a natural language question or click a suggestion chip: "What are my total sales?", "Detect anomalies", "Show profit trends".
  • Use the Analysis Type tabs (Revenue / Profit / Expenses / Trends / Anomalies) for guided one-click analysis.

Configuration

Environment variables and frontend config options

Backend — backend/.env

Create this file from .env.example. Never commit it to version control.

env 
# Flask
SECRET_KEY=your-super-secret-key-change-this
JWT_SECRET_KEY=your-jwt-secret-key
FLASK_ENV=development
FLASK_DEBUG=True

# Supabase
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_KEY=your-supabase-anon-key

# Google OAuth
GOOGLE_CLIENT_ID=your-google-oauth-client-id
GOOGLE_CLIENT_SECRET=your-google-oauth-client-secret

# CORS (comma-separated allowed origins)
CORS_ORIGINS=http://localhost:5500,http://127.0.0.1:5500
VariableRequiredDescription
SECRET_KEY✅ YesFlask session secret key
JWT_SECRET_KEY✅ YesSigns JWT tokens (7-day expiry, HS256)
SUPABASE_URL✅ YesYour Supabase project URL
SUPABASE_KEY✅ YesSupabase anon key
GOOGLE_CLIENT_ID⚠️ OptionalRequired for Google OAuth login
GOOGLE_CLIENT_SECRET⚠️ OptionalRequired for Google OAuth login
CORS_ORIGINS✅ YesComma-separated list of allowed frontend origins
Frontend — js/config.js

The frontend auto-detects the environment based on window.location.hostname. Only one value needs changing for production — the render.com URL:

javascript 
// config.js — auto-switches between dev and production
const API_BASE_URL = (window.location.hostname === 'localhost' ||
                      window.location.hostname === '127.0.0.1')
    ? 'http://localhost:5000/api'           // development
    : 'https://dataxpert-5twp.onrender.com/api'; // production

// Must match GOOGLE_CLIENT_ID in backend .env
const GOOGLE_CLIENT_ID = 'your-google-oauth-client-id';
⚠️ Load order is critical. config.js must be loaded first in every HTML file because all other scripts depend on its exported constants (API_ENDPOINTS, getToken(), DataCache, etc.).

Database Setup

Supabase (PostgreSQL) schema and table descriptions

  1. 1
    Create a Supabase project
    Go to supabase.com, sign up or log in, and click New Project. Choose a region close to your users.
  2. 2
    Copy your credentials
    In the Supabase dashboard go to Settings → API. Copy the Project URL and the anon / public key into your .env file.
  3. 3
    Run the SQL setup
    Open the SQL Editor in Supabase, paste the contents of database.sql from the project root, and run it. This creates all required tables.
  4. 4
    Enable Row Level Security (optional)
    For production, enable RLS on all tables in Table Editor → Policies to ensure users can only access their own data. The backend handles auth via JWT so RLS via the anon key is optional in development.

Google OAuth Setup

Enable Google Sign-In for your DataXpert instance

⚠️ Google OAuth is optional. Email/password login works without it. Skip this section if you don't need Google Sign-In.
  1. 1
    Go to Google Cloud Console
    Visit console.cloud.google.com and sign in with your Google account.
  2. 2
    Create or select a project
    Click the project selector at the top and choose New Project. Give it a name like DataXpert.
  3. 3
    Enable the Google Identity API
    Go to APIs & Services → Library, search for Google Identity (or Google+ API) and click Enable.
  4. 4
    Create OAuth 2.0 credentials
    Go to APIs & Services → Credentials → Create Credentials → OAuth 2.0 Client ID. Select application type Web application.
  5. 5
    Add authorized origins & redirect URIs
    In the credentials form add the following:
    Authorized JavaScript origins 
    http://localhost:5500
http://127.0.0.1:5500
    Authorized redirect URIs 
    http://localhost:5500
http://localhost:5500/index.html
  6. 6
    Copy the Client ID to your config
    Copy the generated Client ID and paste it in two places:
    backend/.env 
    GOOGLE_CLIENT_ID=72842356502-xxxxxxxx.apps.googleusercontent.com
    frontend/js/config.js 
    const GOOGLE_CLIENT_ID = '72842356502-xxxxxxxx.apps.googleusercontent.com';
✅ After saving, the Google Sign-In button on the login page will appear automatically. The GSI SDK is loaded asynchronously via window.onGoogleLibraryLoad for near-instant button rendering.

Project Instructions

Architecture patterns, API conventions, and developer workflow

Architecture & Data Flow

All requests flow through a clean layered architecture:

Frontend (HTML/JS) │ ▼ HTTP Request to /api/* Flask Routes (app.py) │ @token_required decorator validates JWT ▼ Service Classes ├── AuthService → auth/auth_service.py ├── SupabaseClient → database/supabase_client.py └── AI Pipeline → ai/analysis_engine.py ai/nlp_processor.py ai/anomaly_detector.py │ ▼ supabase-py Supabase (PostgreSQL)
API Response Format

All API endpoints return a consistent JSON envelope:

python — success 
return jsonify({'success': True, 'data': result}), 200
python — error 
return jsonify({'success': False, 'message': 'Error details'}), 400

Protected Routes Pattern

All authenticated endpoints use the @token_required decorator. It validates the Bearer token and injects current_user as the first argument:

python 
@app.route('/api/resource', methods=['GET'])
@token_required
def get_resource(current_user):
    # current_user = { id, name, email, ... }
    user_id = current_user['id']
    data = db_client.get_user_data(user_id)
    return jsonify({'success': True, 'data': data})
Frontend Auth Pattern

Always use the helpers from config.js — never access localStorage directly:

javascript 
// Auth helpers (defined in config.js)
const token = getToken();           // read JWT
setToken(data.token);               // save JWT after login
const user  = getUser();            // read user object
setUser(data.user);                 // save user object
clearAuth();                        // remove token + user (logout)
const loggedIn = isLoggedIn();      // boolean check
requireAuth();                      // redirect to index.html if not logged in

// Authenticated fetch using getAuthHeaders()
const headers = getAuthHeaders();   // { Content-Type, Authorization: 'Bearer ...' }

// Or use the unified apiRequest wrapper
const data = await apiRequest(API_ENDPOINTS.DASHBOARD_STATS);
// → auto-attaches Bearer token, handles 401 redirects, throws on failure
Database Access Pattern

Never call supabase client directly in route handlers. Always go through the SupabaseClient class:

python 
# ✅ Correct — use SupabaseClient methods
db_client.get_user_by_id(user_id)
db_client.add_business_data(data_dict)
db_client.get_business_data(user_id)

# ❌ Wrong — never call supabase directly in routes
supabase.table('users').select('*').execute()  # Don't do this
AI Analysis Pipeline

When a user sends a chat message on the AI Analysis page:

  1. 1
    nlp_processor.extract_intent()
    Determines analysis type: sales, profit, trend, or forecast.
  2. 2
    nlp_processor.extract_entities()
    Extracts dates, amounts, and time periods from the message.
  3. 3
    analysis_engine.analyze()
    Performs the analysis (using Pandas/NumPy) based on intent and entities.
  4. 4
    anomaly_detector.detect_anomalies()
    Runs Z-score based outlier detection on the business data.
  5. 5
    Response persisted to database
    Full response saved to chats table; analysis object saved to analysis_results.
